## 修改文件

- `src/campus/CampusScene.ts`：调整白天/夜晚背景、雾、半球光、日/月光、环境反射与曝光；接入天空和分区灯预算；软件 GPU 的 `setTime` 直接应用目标氛围，不等待多帧交叉渐变；滚动跨区时同步更新灯预算。保留原指针、键盘、暂停、能源流、降级与释放逻辑。
- `src/campus/cameraRig.ts`：仅改变 overview 预设，从 `(2.8, 28.8, 52)` 看向 `(5.6, -0.2, 4.2)`，改为 `(3, 19, 55)` 看向 `(5.6, 4.3, 4.2)`；保留家庭、工商业、离网相机路径、移动端拉远和真实拖动。
- `src/campus/campusWorld.ts`：草地与已有玻璃材质对比；屏幕、室内灯芯、工商业窗芯按用途分别设定夜间 emissive；给原真实灯添加名称及区域元数据，不动产品、灯具或地形的几何与位置。
- `src/campus/detailLayer.ts`：让已有概念办公楼玻璃外墙与入口形成暖窗；露营台灯、屏幕、帐篷材质夜间分层更新；无车辆动画、无新增真实灯。
- `src/campus/homeRefinement.ts`：已有家庭侧窗暖光响应，以及原壁灯、庭院灯的预算标签；屋顶、墙体、光伏安装、设备支撑均保持原样。
- `src/campus/lightingBudget.ts`：新增纯预算选择模块。全景先覆盖家庭、道路、离网、工商业；局部 zone 按原距离就近；硬件桌面保留全部灯。
- `src/campus/atmosphericSky.ts`：新增一个 224 三角面的背景天空网格，仅两个颜色 uniform；不投影、不写深度，不需每帧位移或新纹理。
- `src/campus/validate-campus.cjs`：保留原断言并增加灯数/固定 range、分区预算、办公暖窗、天空成本、全景投影、真实相机拖动及软件 GPU 即时氛围等检查。
- `assets/js/campus.bundle.js`：由 `npm run build:campus` 生成，没有手工编辑。
- `docs/visual-campus-refinement.md`：本记录。

## 真实灯与性能约束

仍为 **12 盏真实 Point/Spot 灯**。位置、最大强度、range、decay=2 及 Spot 的锥角/半影均与修改前一致。预算仅影响 `visible`，没有把距离衰减改成假灯光。所有灯具白天强度归零，窗户、暖色灯芯与本轮新增暖色材质 emissive 同样归零。

| 预算 | 全景实际开启的代表性灯 |
| --- | --- |
| 4：软件 GPU | 家庭室内灯、道路第 1 盏灯、离网小屋灯、工商业办公室灯 |
| 6：移动端硬件 GPU | 上述 4 盏，加道路第 2 盏灯和家庭庭院柱灯 |
| 12：桌面硬件 GPU | 全部原灯：室内、两壁灯、两庭院步道灯、庭院柱灯、工商业办公室、两道路灯、离网小屋、离网路灯、露营台灯 |

4 灯预算下其他灯芯仍通过真实灯具已有网格的 emissive 可辨，但没有实际照射周围的额外物理光源；因此不会与全灯档完全相同。概念办公楼暖窗独立于预算，全景不再只剩家庭一块暖光。局部家庭/工商业/离网视角保留就近选灯。

保持原单张方向光阴影：软件 GPU/移动端 1024，桌面 2048。没有局部灯阴影、新依赖、昂贵后期、Bloom、反射通道或车辆更新循环。原世界网格仍为 **262,436** 三角面，新增天空为 **224** 三角面和一次简单背景绘制。软件 GPU 沿用既有像素比与渲染节流；即时昼夜是代码路径保证，未声称已测得浏览器帧率。

## 检查结果

`npm run build:campus`：**通过**。

`node src/campus/validate-campus.cjs`：**通过**，`browserTest: false`。主要结果：

- 12 灯数量、既有固定 range、decay=2；白天灯具与暖色自发光为 0，夜晚对应强度大于 0。
- 4/6/全部预算均覆盖家庭、道路、离网、工商业；局部预算与距离就近选择一致；预算改变不改变灯具物理属性。
- 概念办公楼已有玻璃外墙、入口具有夜间暖色 emissive。
- 全景四个区域代表点位于横屏画框内，镜头俯角低于 20°且留出天空视角；实际 PerspectiveCamera 随拖动变化并正确复位。
- 仍为 3 辆静态停放车辆、338 块屋顶瓦、8 块家庭 PV；无车辆 update 回调。
- 电池与逆变器原位置分别为 `[-14.25, 0.26, 4.68]`、`[-15.8, 2.21, 4.6]`；两台原侧冷却储能柜保留。
- 夜间 PV 能源粒子关闭；能源流显示/隐藏/暂停/减少动态行为与原检查一致；键盘仍局限场景焦点，pointer-cancel 与真实拖动保留。

另外将修改前源码与当前源码分别在内存中构建为真实 Three.js 场景，逐项比较 **1,185 个世界对象**：对象层级、位置、旋转、缩放、几何顶点/索引和实例矩阵完全一致；12 盏灯的物理参数完全一致；热点定义完全一致。新增天空位于世界组之外，未参与改写园区布局。

既有验证脚本运行有 Three.js CommonJS 弃用提示，不影响通过结果。当前项目没有独立 TypeScript 编译器及官方 Three.js 类型声明；自动诊断仍存在既有 Three.js JS 类型推断噪声。本轮未安装依赖，不将 esbuild 构建成功表述为完整 TypeScript 类型检查通过。

## 仍存在的差距与预览边界

这次是取景、光照、材质修正，不是照片级园区重建，也没有补齐参考里的建筑、远山、树冠密度、道路材质细节或产品完整 CAD。相机虽然降低俯视并露出天空，但保留原世界布局，不能复制参考中办公楼、家庭、仓库和露营之间的透视关系；产品图鉴与原功能未扩展。

现有办公楼是简化概念建筑，窗暖光主要依靠现有玻璃材质与已有窗格，不具有参考中的逐房间室内细节。天空只是颜色与空气层次，没有摄影云层、星空或山景。4 灯档下未入选灯具只有灯芯可见，不会产生与全灯档相同的路面光池与真实溢光。

没有修改后浏览器截图，所以“天空占比、夜景最终冷暖平衡、暖窗是否仍过平、实际软件 GPU 帧率与 HUD 遮挡”仍须在现有 Preview 中确认。此次没有发布、推送或 Git 提交，不能宣称已完全达到补充图、照片级真实感或完整模型。
