## 可辨的建筑实体改进

- **侧窗**：原单片侧玻璃替换为两片 12 mm 厚示意玻璃，各自落在真实开口内；增加外框、中梃、内压条、密封条、石材深窗台、滴水槽和抹灰止口。窗玻璃沿用原材质的夜间 0→n 自发光逻辑，不新增窗灯。
- **living 玻璃边界**：沿用 `campusWorld` 中原右半区 3.3×2.9 m 玻璃，不叠加另一层整片玻璃；两门扇边框、横框和胶条包住原玻璃边缘。上/下滑轨采用实际挤出双槽 U 截面；U 形拉手有回弯和基座，不是悬浮直方体。左半区保持开放，可继续看到室内家电。
- **墙脚与立面**：技术翼连续防水基脚、抹灰止口、实体底座砂浆背层及 48 块错缝薄石材砌块。石块之间有真实几何间隔，顶部有压顶；增加 living 室内踢脚线及外侧防水基脚。未用砖缝照片替代几何。
- **木饰面**：右侧原 15 根粗木条替换为 28 根实例化竖向型材；每根具有中央浅凹槽和 2 mm 倒角，板缝是真实留空。UV 按米制坐标生成，长板不会把一幅照片拉满全长。
- **梁与檐口**：保留原前梁柱，仅补端部承托、原屋顶坐标系中的 32 块檐底木板和 5 处椽尾构件。未重做整栋屋顶。
- **雨水排放**：厚壁开口半圆雨槽、两条卷边、封闭端盖、13 组支撑箍/挂座、出口套筒、转折落水管、3 组接缝套管/墙箍/墙座和落地溅水石。落水管由屋顶真实变换计算接口位置，独立于电气导管。
- **庭院铺装**：95 块实例化实体铺装砖；细缝为真实砖边留空。横向门前铺装连接左侧服务区域与开放入口，中央路径和左侧支路延伸到原庭院/车道，不穿过既有矮柱灯或跨区重建道路。铺装顶面为 homeBody 局部 y=-0.005 m，与既有家庭台地接近齐平；门槛保持原较高地台关系，增加低边界与入口落地边线。

原 `BatterySupportPaver`、四个 `BatteryWheelContact` 和两个 `ConceptMountingRail` 仍留给父任务替换/移除。铺装在这些旧电池支撑位置周围主动留空；本模块不校准设备尺寸、不推测未知产品接线口、安装孔或认证。

## 材质接入与资源生命周期

父任务约定的 `TextureBundle.homePbr?: { plaster, timber, paving }` 已在入口接入，每套为 `{ color, normal, roughness, ao? }`。入口和新建筑实体共用这一来源约定，但不会修改 `textures.ts` 的加载或释放实现。

- PBR 到位时，底色用白色，避免旧深色乘新底图造成二次变暗；无 PBR 时保留原程序灰泥 fallback，并使用非摄影石材/木材颜色与 roughness。
- 建筑实体按米制 UV 铺贴，当前一套图覆盖 2 m；`architecture.setSurfaceMaps(surface, { map, normalMap, roughnessMap, aoMap, metresPerTile, color })` 可改重复尺度。`surface` 为 `plaster / wood / stone`。
- 灰泥/木材/铺装法线强度分别为 0.15 / 0.2 / 0.3。仅法线、粗糙度和可选 AO，不使用位移细分。
- 本模块克隆 PBR Texture 保留独立 repeat，克隆仍共享父源 image；模块 dispose 只释放自身克隆、材质和几何，不释放父任务拥有的源贴图。
- `planting.setLeafMaps(map?, normalMap?, roughnessMap?)` 留有单叶贴图接口；调用者拥有这些可选贴图。当前叶片是几何/非摄影配色，并未假称已经下载了真实植物叶纹理。

父任务报告已核实 ambientCG CC0 `Plaster001 / Wood079 / PavingStones128` 并负责下载、加载、记录许可与回调。本子模块未自行搜索、下载或独立复核这些资产；最终资产证据以父任务的下载和来源记录为准。屋面瓦、叶片、花瓣和盆土目前仍为几何与程序配色，没有新增摄影素材。

## 明确剩余不足
